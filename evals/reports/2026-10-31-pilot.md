## Setup and evidence

Sixteen fresh host agents ran once each: one baseline and one Batman run per scenario. Agents inherited the same parent configuration with no model overrides. Tasks and fixture contents were identical within each pair. Neutral workspace names and shuffled execution order reduced outcome hints. Baseline received ordinary engineering instructions; Batman additionally received the skill and its relevant references.

Both variants were instructed to use at most five inspection/verification tool calls, return at most 250 words, and keep the target read-only. One additional call could save the final response outside the target. Batman's skill-loading calls were included in the same requested inspection budget. Budget compliance was not independently audited. The fixtures remained byte-for-byte unchanged after all trials.

[Raw final responses and metadata](2026-10-31-pilot.json) include fixture hashes and the skill-core hash. Reported commands and inspections are agent claims: raw tool traces were not exported and are not scored as independently verified inspection. Deterministic tests separately reproduce the fixture behaviors. These are host-agent trials, not Promptfoo provider runs or native Codex/Claude executions.

The author model assessed the core conclusions against `METHODOLOGY.md` with variant identity visible. There was no blinded human review or calibrated LLM judge. The result is a coarse answer-level pass assessment, not the weighted six-dimension quality score.

Average responses were 167.25 whitespace-separated words for baseline and 180.375 for Batman, about 7.8% longer for Batman. This measures output length only. Token use, cost, runtime, exact model version, and independently enforced execution budgets were not captured. No efficiency claim follows from these word counts.

## Limits and next experiment

One sample per scenario is insufficient to estimate reliability or statistical significance. The fixtures are tiny, and some tasks explicitly ask for consumer inspection or assumption checks; capable baseline agents already solve them. The correct control is only one case, so zero observed false positives there is not a general false-positive rate.

Keep the existing suite as smoke coverage. Next, add larger repositories with unrelated code, indirect consumers, realistic ticket ambiguity, and multiple correct controls. Run at least three samples per variant with captured tool traces, pinned model/version and resource metadata, and blind grading before claiming an improvement.
